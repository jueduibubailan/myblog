# **一、概要**

## **1、标题**

启发式算法的发展（启发式进化算法）：使用大语言模型进行高效的自动算法设计

## **2、启发式算法的用处**

* 解决复杂的搜索和优化问题；
* 使用 AHD（自动启发式设计），同时利用 LLMS 和 EC 的优势；
* 关键逻辑（key logic）：让机器自动进化「如何设计启发式算法」的思路。

## **3、人工设计的启发式算法的缺点**

非常费力，需要丰富的工作经验和知识，是许多应用程序领域的瓶颈。

## **4、该文章使用的方法**

利用大型语言模型（LLMS）和进化计算（EC）方法进行自动启发式设计（AHD）的新型进化范式——**启发式进化算法（EOH）**。

### **进化搜索框架**

进化搜索框架中的**思想（thoughts）和代码（codes）的进化**，使得它对于生成高性能的启发式算法非常有效和高效。

### **对于在线装箱问题**

EOH 生成的启发式算法以较低的计算预算（就对 LLM 的查询数量而言），显著优于广泛使用的人工制作的基线算法。

## **5、相关内容解读**

* **手工设计**：人工将想法（thoughts）转化为算法；
* **Evolution of Codes（FunSearch）**：使用 LLM 将想法转化为代码。它将 AHD 建模为函数空间中的搜索问题，其中每个函数都是由程序表示的启发式函数，它使用进化框架中的 LLMS 迭代地提高生成函数的质量。

### **缺点**

机制不是很高效，并且需要非常大量的计算资源来生成高质量的启发式算法。

* **Evolution of Both Thoughts and Codes（EOH，本文）**：先使用 LLM 将想法变为思想（thoughts），再用 LLM 将思想变为代码（codes）。

## **6、AHD（Automatic Heuristic Design）**

* 自动为给定的问题类别选择、调整或构建有效的启发式规则；
* GP（Genetic Programming，遗传编程）已在 AHD 中使用，但它需要一组允许的原语或变异操作来定义和生成启发式规则。

## **7、现状**

具有快速工程（prompt engineering）的独立 LLM 可能不足以在现有知识之外产生新颖和有用的想法。

## **8、文章的主要工作**

1. 提出了一种新的范式 EOH：它使用 LLMS 进化**思想（thoughts）和代码（codes）**，从而以最少的手工设计和不需要领域模型训练的方式自动设计启发式算法；
2. 开发了几个简单但有效的**提示策略（prompt strategies）**来引导 LLMS 生成更多样化和更有效的启发式方法，这些提示策略普遍适用于其他 LLM 辅助搜索方法；
3. 对三个广泛研究的组合优化基准问题进行了综合评价，证明了 EOH 方法的性能优于现有的许多 AHD 方法。特别是，EOH 发现启发式算法的性能比 FunSearch 设计的算法更好；在解决在线装箱问题时，EOH 使用的查询比 FunSearch 少得多。

# **二、背景**

## **1、Automatic Heuristic Design自动启发式设计**

**缺点**：需要手工制作的算法组件和领域知识。

## **2、LLMs for Heuristic Design启发式设计中的LLMS**

* 大多数采用 LLM 作为优化器，通过情景学习（in-context learning）直接生成新的试验解决方案；
* 其他人则集成 LLM 来辅助算法设计：提取深层算法特征进行启发式选择、为启发式选择提供指南、设计算法组件。

**缺点**：设计一个有竞争力的启发式算法仍然困难。

## **3、LLMs + EC（大语言模型＋进化算法）**

**结论**：Evolution of Heuristics（EoH）。

### **1、主要目标**

进化**思想和代码**，以模仿人类专家进行的启发式开发过程。

### **2、EOH是为了解决某一特定问题**

EOH 面向的是「为某个具体问题自动设计高性能启发式算法」这一任务：给定问题的定义与评估环境，自动进化出该问题专用的启发式规则，而不是直接求解某个实例。

### **3、研究方向**

* **想法的演变（evolution of "thoughts"）**：让 LLM 在思想层面总结、重组与创新；
* **代码的演变（evolution of codes）**：让可执行代码随思想一起迭代进化。

### **4、进化框架Evolution Framework**

* 设计了**五种快速策略（prompt strategies）**来生成新的启发式方法；
* 每一代中，每个策略被调用 N 次，以生成 N 个启发式规则；
* 将在问题实例上评估每个新生成的启发式规则，并在可行的情况下将其添加到当前种群；
* 每代最多向当前种群添加 **5N** 个新的启发式算法；
* 从当前种群中选择 N 个最好的个体解来形成下一代的种群。

### **5、启发式表示法**

**启发式算法的组成：**

1. 用自然语言描述（thought）；
2. 预定义格式的代码块（code）；
3. 适应值（fitness）。

**给出三个基本组件来格式化代码块：**

1. 函数名称；
2. 输入变量；
3. 输出变量。

**6、快速策略 Prompt Strategies（初始化提示 Initialization prompt）**

使用 LLMS 来创建所有初始启发式规则，从而消除了对专家知识的需求。

**Evolution prompts（进化提示）**

**探索组（Exploration）**

* **E1**：生成与父启发式尽可能不同的新启发式；
* **E2**：探索与选定的父级启发式算法思想相同的新启发式算法。

**改造组（Modification）**

* **M1**：修改一个启发式规则以获得更好的性能；
* **M2**：修改一个选定启发式的参数；
* **M3**：通过删除冗余组件来简化启发式算法。

# **一、第二轮学习**

## **1、关键名词学习**

### **a、启发式进化（EoH）**

它结合大型语言模型（LLMs）和进化计算（EC）方法来实现自动启发式设计（AHD）。

### **b、进化计算（EC）**

进化计算（Evolutionary Computation）是一类同时维护多个候选解（种群，population）的优化方法：把表现更好的解留下来（选择，selection），把不同解的“优良片段”重新组合（交叉，crossover），再用少量随机扰动维持多样性并开拓新区域（变异，mutation），从而在一代又一代的迭代中逐步找到更优解。它最大的特点是：即使目标函数不可导、地形崎岖、约束复杂，只要“能评估好坏”（能算出分数/适应度），就能推动搜索向更好的方向前进。

**定义**

* 同时保留多个候选解，并基于评估结果生成下一代候选解的搜索式优化框架；
* 每个候选解通常以类似“基因型（genotype）”的形式编码；编码方式（表示）往往决定了搜索效率与可扩展性；
* 不依赖目标函数梯度信息；只要能计算适应度/得分，就能进行迭代更新；
* 偏向全局搜索，旨在降低被局部最优困住的风险（当然并非总能避免）。

**核心算子**

* **选择（selection）**：让表现更好的个体在下一代中拥有更高的保留或繁殖概率；
* **交叉（crossover）**：从两个（或多个）个体中重组片段生成新个体，期望把“好基因”重新拼装到一起；
* **变异（mutation）**：对个体做小幅随机扰动，用于维持多样性、探索未覆盖区域，并防止过早收敛。

三者失衡会带来典型问题：选择压力过大易多样性崩塌（早熟收敛），扰动过强则可能退化为低效的随机搜索。

**按代迭代的优化流程**

1. 初始化种群，并评估每个候选解的适应度（fitness）；
2. 根据适应度进行选择；再通过交叉与变异产生子代，组成下一代种群；
3. 不断重复，使种群整体（如平均/最优适应度）呈上升趋势；
4. 常见终止条件：达到最大代数、性能达到阈值、长时间无明显改进等。

**典型变体与应用场景**

* **遗传算法（Genetic Algorithm, GA）**：最经典的形式之一，常见二进制/实数编码与标准交叉变异算子；
* **进化策略（Evolution Strategies, ES）**：更偏重连续空间中的变异与稳健更新，在工程优化与黑盒优化中非常常见；
* **遗传编程（Genetic Programming, GP）**：把“程序结构/表达式结构”作为个体进行进化，用来发现规则、公式或策略。

非常适合“只能评估、难以求导”的任务：模型结构搜索、超参数调优、复杂系统的设计优化等。

### **c、启发式算法**

**i、模拟退火算法（简单局部搜索）**

模拟退火算法来源于固体退火原理，将固体加温至充分高，再让其徐徐冷却，加温时，固体内部粒子随温升变为无序状，内能增大，而徐徐冷却时粒子渐趋有序，在每个温度都达到平衡态，最后在常温时达到基态，内能减为最小。

模拟退火算法从某一较高初温出发，伴随温度参数的不断下降，结合一定的概率突跳特性在解空间中随机寻找目标函数的全局最优解，即在局部最优解能概率性地跳出并最终趋于全局最优。

**数学原理：**

k 即是冷却系数，温度按 $T \leftarrow k \cdot T$ 逐步降低。

如果新解比当前解更优，则接受新解，否则基于 `Metropolis` 准则判断是否接受新解。接受概率为：

$$P(\text{accept}) = \begin{cases} 1, & \Delta E \le 0 \ \exp\left(-\dfrac{\Delta E}{T}\right), & \Delta E > 0 \end{cases}$$

假设开始状态在 `A`，随着迭代次数更新到 `B` 局部最优解，这时发现更新到 `B` 时，能量比 `A` 要低，则说明接近最优解了，因此百分百转移。状态到达 `B` 后，发现下一步能量上升了：如果是梯度下降则是不允许继续向前的，而这里会以一定的概率跳出这个坑，这个概率和当前的状态、能量等都有关系。如果 `B` 最终跳出来了到达 `C`，又会继续以一定的概率跳出来，直到到达 `D` 后，就会稳定下来。

**流程**

算法实质分两层循环，具体流程为：

1. **内层循环（某一温度下的平衡搜索）**：在当前温度 T 下，对当前解进行扰动产生新解，依据 Metropolis 准则决定是否接受新解，反复迭代直到该温度下达到平衡态；
2. **外层循环（降温）**：按冷却系数 k 降低温度（$T \leftarrow k \cdot T$），然后回到内层循环；不断重复，直到温度足够低或满足终止条件，输出当前最优解。

**应用**

* **模拟退火算法在** `VLSI` **设计中的应用**：利用模拟退火算法进行 `VLSI`（`Very Large Scale Integration`，超大规模集成电路）的最优设计，是目前模拟退火算法最成功的应用实例之一。用模拟退火算法几乎可以很好地完成所有优化的 `VLSI` 设计工作，如全局布线、布板、布局和逻辑最小化等等。
* **模拟退火算法在图像处理中的应用**：模拟退火算法可用来进行图像恢复等工作，即把一幅被污染的图像重新恢复成清晰的原图，滤掉其中被畸变的部分。因此它在图像处理方面的应用前景是广阔的。
* **模拟退火算法在神经网计算机中的应用**：模拟退火算法具有跳出局部最优陷阱的能力。在 `Boltzmann` 机中，即使系统落入了局部最优的陷阱，经过一段时间后，它还能再跳出来，系统最终将往全局最优值的方向收敛。
* **模拟退火算法的其他应用**：除了上述应用外，模拟退火算法还用于其它各种组合优化问题，如 `TSP` 和 `Knapsack` 问题等。大量的模拟实验表明，模拟退火算法在求解这些问题时能产生令人满意的近似最优解，而且所用的时间也不很长。

**爬山算法（简单局部搜索）**

是一种简单的贪心搜索算法，该算法每次从当前解的临近解空间中选择一个最优解作为当前解，直到达到一个局部最优解。

其主要缺点是会陷入局部最优解，而不一定能搜索到全局最优解。

**ii、禁忌搜索TS（简单局部搜索）**

是一种亚启发式随机搜索算法，它从一个初始可行解出发，选择一系列的特定搜索方向（移动）作为试探，选择实现让特定的目标函数值变化最多的移动。为了避免陷入局部最优解，TS 搜索中采用了一种灵活的“记忆”技术，对已经进行的优化过程进行记录和选择，指导下一步的搜索方向。

**基本思想**

1. 避免在搜索过程中的循环；
2. “只进不退”的原则，通过禁忌表实现；
3. 不以局部最优作为停止准则；
4. 邻域选优的规则模拟了人类的记忆功能。

**(1) 编码方式**

将不相同的 n 件物品分为 m 组，可以用的编码：

* **a、带分隔符的顺序编码**：以自然数 1~n 分别代表 n 件物品，n 个数加上 m-1 个分割符号混编在一起，随机排列。如：`1-3-4-0-2-6-7-5-0-8-9`；
* **b、自然数编码**：编码的每一位分别代表一件物品，而每一位的值代表该物品所在的分组。如：`1-2-1-1-2-2-2-3-3`。

**(2) 初始解的获取**

可以随机给出初始解，也可以事先使用其他启发式等算法给出一个较好的初始解。

**(3) 移动邻域**

移动是从当前解产生新解的途径，例如上述问题中用移动 s 产生新解 s(x)。从当前解可以进行的所有移动构成邻域，也可以理解为从当前解经过“一步”可以到达的区域。

**(4) 禁忌表**

禁忌表的作用：防止搜索出现循环。

* 记录前若干步走过的点、方向或目标值，禁止返回；
* 表是动态更新的；
* 表的长度称为 Tabu-Size。

**禁忌表的主要指标（两项指标）**

* **禁忌对象**：禁忌表中被禁的那些变化元素；
* **禁忌长度**：禁忌的步数。

**禁忌对象（三种变化）**

* 以状态本身或者状态的变化作为禁忌对象；
* 以状态分量以及分量的变化作为禁忌对象；
* 采用类似的等高线做法，以目标值变化作为禁忌对象。

**禁忌长度**：可以是一个固定的常数（T=c），也可以是动态变化的，可按照某种规则或公式在区间内变化。

* 禁忌长度过短，一旦陷入局部最优点，出现循环无法跳出；
* 禁忌长度过长，候选解全部被禁忌，造成计算时间较大，也可能造成计算无法继续下去。

**(5) 渴望水平函数**

$A(x, s)$ 一般为历史上曾经达到的最好目标值，若有 $C(s(x)) < A(x, s)$，则 $s(x)$ 是不受禁忌表限制的；即使 $s(x) \in T$，仍可取 $x = s(x)$。$A(x, s)$ 称为渴望水平函数。

**(6) 停止准则**

1. 给定最大迭代步数（最常用）；
2. 设定某个对象的最大禁忌频率；
3. 设定适配值的偏离阈值。

**iii、迭代局部搜索**

局部搜索算法是从[爬山法](https://zhida.zhihu.com/search?content_id=9355463&content_type=Article&match_order=1&q=%E7%88%AC%E5%B1%B1%E6%B3%95&zhida_source=entity)改进而来的。简单来说，局部搜索算法是一种简单的贪心搜索算法，该算法每次从当前解的邻域解空间中选择一个最好邻居作为下次迭代的当前解，直到达到一个局部最优解（local optimal solution）。局部搜索从一个初始解出发，然后搜索解的邻域，如有更优的解则移动至该解并继续执行搜索，否则就停止算法获得局部最优解。

迭代局部搜索属于探索性局部搜索方法（EXPLORATIVE LOCAL SEARCH METHODS）的一种。它在局部搜索得到的局部最优解上，加入了**扰动**，然后再重新进行局部搜索。

**过程**

迭代局部搜索过程：

1. 初始状态：`best_solution`（最优解）、`current_solution`（当前解）；
2. 从初始解（`best_solution`）中进行局部搜索，找到一个局部最优解 $s\_1$（`best_solution`）；
3. 扰动 $s\_1$（`best_solution`），获得新的解 $s\_2$（`current_solution`）；
4. 从新解 $s\_2$（`current_solution`）中进行局部搜索，再次找到一个局部最优解 $s\_3$（`best_solution`）；
5. 基于判断策略，对 $s\_3$（`current_solution`）好坏进行判断，选择是否接受 $s\_3$（`current_solution`）作为新的 `best_solution`；
6. 直到达到边界条件，不然跳回第 2 步一直循环搜索。

### **d、遗传编程（GP）**

GP 需要一组允许的基本操作或变异运算来定义和生成启发式方法。

**先导**

遗传编程以树形程序为个体，交叉是产生新个体的核心算子之一（原笔记此处为交叉示意图，现以文字说明）：

* **单点和多点交叉示例**：单点交叉在两个父代树上各选一个交叉点，交换以交叉点为根的两棵子树；多点交叉则在多个位置同时交换子树，后代变化更明显；
* **均匀交叉（上为交叉后，下为交叉前）**：逐节点决定从哪个父代继承内容，混合程度更高、后代多样性更强。

**理论计算**

遗传编程的理论计算主要借鉴遗传算法的**模式定理（Schema Theorem）与积木块假设**：较短、适应度较高、阶数较低的模式在进化中更容易被保留与重组。由于 GP 的个体是不定长的树形程序，理论分析通常比定长编码的 GA 更复杂，一般关注：

* 个体树的大小（节点总数）与深度对搜索效率的影响；
* 种群规模、进化代数与收敛性之间的关系；
* 程序规模增长问题（bloat）：进化后期树容易过度膨胀，通常需要限制最大深度或施加规模惩罚。

（原笔记此处为理论计算相关图片，现以文字概述代替。）

**局限性**

遗传算法是对字符串进行操作，逐步实现进化遗传。许多研究人员在此基础上提出的理论和方法，极大地丰富了遗传算法的内容。然而，用编码方法特别是定长字符串方法描述问题，极大地限制了遗传算法的应用范围。遗传算法的主要缺点如下：

1. **不能描述层次化问题**：有许多问题的自然描述是层次化的结构，而不是线性结构。例如数学表达式 $f(x) = ax + b$ 可以表示为层次化的树结构（根为加法，子节点为乘法和变量），这种非线性结构用线性字符串来描述就相当困难。
2. **不能描述计算机程序**：如方程求解、数据回归，或者有分支、循环、递归的算法程序；
3. **线性字符串缺乏动态可变性**：字符串的长度一旦确定，就比较难以改变，限制了问题的表示。

遗传编程用非线性结构表示个体，因此弥补了遗传算法的部分缺点。它的实质是用广义的计算机程序来求解问题，基本思想是产生一个初始种群，然后根据适者生存原则，用遗传操作来处理这些个体，一代一代更替，使个体越来越接近问题的解。一般而言，遗传编程是基于遗传算法的基础上发展起来的新的进化算法，它克服了遗传算法的部分缺点，具有更大的通用性。

**算法流程**

1. 确定个体的表达方式，表现为确定函数符集、终止符集；
2. 随机产生初始群体；
3. 计算群体中各个体的适应度；
4. 执行遗传操作，包括复制、交换、突变等；
5. 循环执行（3）、（4）直至满足终止条件。

**遗传编程基础**

函数符集 F 内的函数可以为：

* 算法运算符：+、-、×、÷ 等（其中除号为防止计算机溢出，规定分母不为零，称为保护性除法。一旦遇到分母为零时，最简单的处理方法令其商为被除数，或重新选择算术运算符）；
* 超越函数：sin、cos、log、exp 等（其中 log 要防止处理小于或等于零的自变量，采用保护性对数）；
* 布尔运算符：AND、OR、NOT 等；
* 条件表达式：If-then-else、Switch-case 等；
* 循环表达式：Do-until、While-do、For-do 等；
* 控制转移说明语句：Go to、Call、Jump 等；
* 变量赋值函数：a = 1，Read、Write 等；
* 其他定义的函数。

终止符集是变量或常量。

**个体的树形表示**

设函数符集为：$F = {+, -, \times, \div}$（算法中允许出现的运算/函数）；

终止符集为：$T = {x, y, 1}$（变量与常量，作为树的叶子）；

由 F 和 T 组成的个体就是一个层次化的树形结构：内部节点取自函数符集 F，叶子取自终止符集 T。例如表达式 $x \times (y + 1)$ 可表示为根节点为 ×、左叶子为 x、右子树为 +(y, 1) 的树。

**初始个体生成原理**

初始群体由众多初始个体组成，初始个体为所要解决问题的各种可能的符号表达式，它通过随机方法产生。

开始时在函数集 F 中按均匀分布随机地选出一个函数作为算法树的根结点。通常把根结点限制在函数集 F 中是为了生成一个层次化的复杂结构；相反，若从终止符 T 中随机选取根结点，则生成只有一个终止符的退化结构。一般情况下，从函数集中选出的函数 f 如果具有 Z(f) 个自变量，那么就要从该结点发出 Z(f) 个子节点。然后，对于每个子节点，从函数集 F 和终止符 T 的并集 $C = F \cup T$ 中再按均匀分布随机地选出一个元素作为该条线的尾结点。如果此时选出的是一个函数，则重复执行上述过程；如果从并集 C 中选出的是终止符，它作为从节点发出的尾节点，则该分支点上的树就终止生长。上述过程从上到下、从左到右不断重复，直到一棵完整的树生成。

初始群体中的初始个体通过某种随机方法产生：从根节点开始，自上而下、自左而右地随机选取函数或终止符，不断生长分支，最终生成一棵完整的表达式树。

常用的初始个体的生成方法有三种，即**完全法、生长法和混合法**：

* **(1) 完全法（full）**：完全法产生的初始个体，每一叶子的深度都等于给定的最大深度。所谓叶子的深度是指叶子距树根的层次。首先从函数集 F 中选取元素作为根节点，然后根据给定的最大深度分别从函数集 F 及终止符 T 中选取元素。假若待定节点的深度小于给定的最大深度，则该节点从函数集中随机选取，以便算法树延伸；若待定结点的深度等于给定的最大深度，则该节点从终止符集中选取，以便终止算法树的生长。
* **(2) 生长法（grow）**：用生长法形成的初始个体，每一叶子的深度不一定都等于给定的最大深度，但是算法树的最大深度要等于给定值。它也同样首先从函数集 F 中选取根节点，然后再选取外延的待定节点。假若待定节点的深度小于给定的最大深度，则该节点从函数集 F 及终止符 T 的并集 $C = F \cup T$ 中选取；若待定结点的深度等于给定的最大深度，则该节点仅从终止符集中选取，以便终止算法树的生长。
* **(3) 混合法（ramped half and half）**：混合法是完全法和生长法的两者的综合。其实现方法是：初始个体的深度在 2 至给定的最大深度之间随机选取，然后一半的初始个体用完全法产生，另一半的初始个体用生长法产生。

**个体评价（适应度值度量）**

常见的适应度度量有以下四种：**原始适应度、标准适应度、调和适应度和归一化适应度**。

**4.1 原始适应度（raw fitness）**

原始适应度是以求解问题本身的自然属性来陈述的。种群 t 中某一个个体 i 的原始适应度 $r(i, t)$ 可以定义为：

$$r(i, t) = \sum\_{j=1}^{N\_c} |p(i, j) - c(j)|$$

式中，$p(i, j)$ 是个体 i 在实例 j 下计算的返回值，$N\_c$ 是适应度计算实例数目，$c(j)$ 是适应度计算实例 j 的准确值。

原始适应度有时越大越好，有时越小越好，常采用的原始适应度形式有：

1. 预测问题中，用预测值和实际值的离差衡量，越小越好；
2. 模式识别问题中，用匹配的像素点数目衡量，越大越好；
3. 机器人控制中，用碰壁次数衡量，越小越好；
4. 分类问题中，用正确分类的次数衡量，越大越好；
5. 人工生命问题中，用发现或吃掉的食物数衡量，越大越好；
6. 博弈问题中，用赢取的货币衡量，越大越好。

**4.2 标准适应度（standardized fitness）**

鉴于原始适应度有时越大越好，有时越小越好，为了统一衡量标准引出了标准适应度 $s(i, t)$，即标准适应度总是表现为数值越小适应性越好。于是有两种情况发生：

1. 对于原始适应度愈大愈好（如人工蚂蚁问题，若使人工蚂蚁吃掉的食物块数越多越好，则原始适应度越大越好），则按下式计算：

$$s(i, t) = r\_{max}(t) - r(i, t)$$

1. 对于原始适应度为越小越好（如对于最优控制问题，若使控制成本越小越好，则原始适应度越小越好），则标准适应度等于原始适应度，即：

$$s(i, t) = r(i, t)$$

**4.3 调整适应度（adjusted fitness）**

子代 t 中个体的调和适应度 $a(i, t)$ 由标准适应度计算而得。其计算公式：

$$a(i, t) = \frac{1}{1 + s(i, t)}$$

通常 $s(i, t) > 0$，则 $a(i, t) \in [0, 1]$，且调和适应度越大，个体越优良。当标准适应度接近于 0 时，调和适应度具有扩大标准适应度微小差别的好处。这一情况常常出现在进化的最后几代中。随着群体的不断进化，重点就将逐渐放在区分好的和更好的个体上，它们的差别往往很小，特别是当接近一个正确答案时，标准适应度接近。这时调和适应度的扩张能力就显得特别有效。例如，当标准适应度取值介于 0（最佳）和 64（最差）之间时，标准适应度为 64、63 的两个较差个体的调和适应度分别为 0.0154、0.0156，其差别为 0.0002；但是，标准适应度为 4、3 的两个优良个体的调和适应度分别为 0.20、0.25，其差别为 0.05。

**4.4 归一化适应度（normalized fitness）**

个体的归一化适应度 $n(i, t)$ 采用下式进行计算：

$$n(i, t) = \frac{a(i, t)}{\sum\_{j} a(j, t)}$$

**基本算子**

**5.1 复制**

当复制发生时，一个父代个体繁殖一个后代个体。复制过程由两部分组成：首先，根据适应度从群体中选出一个父代个体；其次，被选出的父代个体在未经任何变化的条件下从当前代复制到新一代。根据适应度，一般有以下几种方法：

**（1）比例选择法：**按个体适应度占总适应度之和的比例作为被选择概率，适应度越高的个体越容易被复制到下一代。

**（2）分级选择法：**先按适应度排序分级，再按等级分配选择概率，而不是直接使用适应度数值，避免个别极优个体主导整个种群。

**竞争选择法：**每次随机抽取一小部分个体进行“竞争”，从中选出适应度最高的个体复制到下一代（即锦标赛选择）。

**精英选择法**：将当前代中适应度最优的若干个个体直接复制到下一代，保证进化过程中最优解不丢失。

**交叉（Crossover）**

选择和复制出来的个体还要进行交叉，对每一对个体，产生一个随机数，如果这个数小于交叉概率 $P\_c$，将对个体执行交叉操作。

交叉（Crossover）模拟的是自然界中的遗传以及两性生殖过程，父代通过 DNA 重新组合，产生子代，子代继承了父代的一些基因，同时产生了新的基因。

交叉操作的实现步骤如下：首先选择父代，然后，在每个父代个体中随机选取某个结点作为交叉点，交换父代中以交叉点为根结点的相应子树，得到两个新后代。

**变异（Mutation）**

变异（Mutation）模拟的是生物界中基因突变。交叉只对现有的基因进行排列组合，产生不出新的基因材料，容易发生“早熟”现象，而变异有利于形成群体的多样性，使算法有机会从局部最优解中解脱出来。

对于每一个个体，产生一个随机数，如果它小于变异概率 $P\_m$，则对此个体执行变异操作。产生变异的一般方法是：在个体上随机选定一个变异点，变异点一般选择除根之外的任意节点，删掉以变异点为根的子树，然后用随机方法产生新的子树（方法同初始个体的产生方法相同）插入到该变异点处，变异之后的个体树不能超出最大深度限制。

### **e、FunSearch**

FunSearch 将一个预训练语言模型与自动“评估器”结合，前者提出创造性代码解决方案，后者过滤错误 ideas。通过双方迭代，初步解决方案“进化”为新知识。该系统搜索计算机代码形式的“函数”，因此命名为 FunSearch。

这是首次使用大型语言模型在科学和数学难题上取得新发现。FunSearch 找到了悬而未决的数学公开问题——[盖子集问题](https://zhida.zhihu.com/search?content_id=237551935&content_type=Article&match_order=1&q=%E7%9B%96%E5%AD%90%E9%9B%86%E9%97%AE%E9%A2%98&zhida_source=entity)的新解决方案。此外，为证明其实用性，我们利用它发现了更高效的算法来解决“装箱”问题，在数据中心提效等方面具有广泛应用。

科学进步依赖于分享新认知。FunSearch 强大之处在于，它输出详细揭示解决方案构造方式的代码，而不仅是结果。我们希望这可以激发科学家取得更深入洞察，形成良性循环。

**流程**

1. **输入：Specification（任务规范）**：作为整个流程的起点，它定义了要解决的具体问题，通常包括问题的自然语言描述、输入输出格式的要求，以及用于评估算法好坏的评分标准（例如：运行时间、内存占用、解决方案的质量等）。作用相当于给 LLM 的“考题”和“评分规则”。
2. **核心引擎：Pre-trained LLM（预训练大语言模型）**：这是一个通用的、未经针对特定问题微调的大语言模型（如 PaLM 2）。它是创新的源头，读取“任务规范”和“提示词（Prompt）”，尝试编写出解决问题的代码。关键在于，它不仅仅是模仿，而是会尝试新的函数组合和逻辑，从而可能产生超越人类现有知识的算法。
3. **引导机制：Prompt（提示词）与 Programs database（程序数据库）**：这是 FunSearch 运作的关键。Programs database 存储了历次迭代中已经生成并被评估过的程序，随着时间推移，这个库里会积累大量高质量的程序。Prompt 构建：系统在提示词中会包含数据库里的部分优秀程序作为示例，相当于告诉 LLM：“看看这些前人的优秀作品，在此基础上发挥你的创造力。”通过不断向 LLM 展示历史上好的样本，引导它生成更好的代码，实现“站在巨人肩膀上”的进化。
4. **筛选：Evaluation（评估）**：代表对 LLM 生成代码的测试。LLM 一次会生成多个候选程序，这些程序会被放入评估器中运行，在具体的测试案例上计算分数。用红叉（❌）和绿勾（✅）表示评估的筛选过程：表现差的代码（低分）会被淘汰，表现优异的代码（高分）会被保留。
5. **循环与输出**：被保留的优秀程序会通过实线箭头写回到 `Programs database` 中，这完成了一次进化闭环，数据库因此不断更新。同时，这些优秀程序也会通过虚线箭头反馈给 LLM，作为下一轮生成时的参考素材。经过多轮迭代，系统最终从数据库中筛选出得分最高的程序，输出为 **Novel program**（新颖程序），即整个流程的最终结果。

## **2、实验方法**

### **a、在线装箱问题**

[装箱](https://link.zhihu.com/?target=https%3A//en.wikipedia.org/wiki/Bin_packing_problem)（bin packing）是一类与任务安排和资源配置相关的组合优化问题，主要包含两大要素：物品（items）和箱子（bins）。经典的装箱问题可以表述为：给定若干个物品，每个物品都有对应的尺寸，要求将所有物品放入若干个有相同容量的箱子中，使得每个箱子中的物品尺寸之和不超过箱子容量，并使所用的箱子数目最少。

### **b、旅行商问题**

一个售货员必须访问 n 个城市，恰好访问每个城市一次，并最终回到出发城市。售货员从城市 i 到城市 j 的旅行费用是一个整数，旅行所需的全部费用是他旅行经过的各边费用之和，而售货员希望使整个旅行费用最低。

（等价于求图的最短哈密尔顿回路问题）令 $G = (V, E)$ 是一个带权重的有向图，顶点集 $V = (v\_0, v\_1, ..., v\_{n-1})$。从图中任一顶点 $v\_i$ 出发，经图中所有其他顶点一次且只有一次，最后回到同一顶点 $v\_i$ 的最短路径。

### **c、流水作业调度问题**

**问题描述**：n 个作业 ${1, 2, ..., n}$ 要在由机器 M1 和 M2 组成的流水线上完成加工。每个作业加工的顺序都是先在 M1 上加工，然后在 M2 上加工。M1 和 M2 加工作业 i 所需的时间分别为 $a\_i$ 和 $b\_i$。要求确定这 n 个作业的最优加工顺序，使得从第一个作业在机器 M1 上开始加工，到最后一个作业在机器 M2 上加工完成所需的时间最少。

## **一、核心算法流程**

EoH 将**启发式本身**作为进化个体（而非传统 EA 的解空间），用 LLM 替代遗传编程的变异/交叉算子，实现双表示协同进化。

### **前置定义**

* 个体表示：每个启发式 $h\_i = (thought\_i, code\_i, f\_i)$，其中 `thought` 是自然语言描述的高层逻辑，`code` 是对应的 Python 可执行函数，$f\_i$ 为适应度；
* 父代选择概率：按适应度排名 $r\_i$（越小越好）加权随机选择，公式为 $p\_i \propto \dfrac{1}{r\_i + N}$（N 为种群大小），既偏向优质个体也保留多样性，避免早熟；
* 每代生成量：5 种 prompt 策略各调用 N 次 LLM，单代最多生成 5N 个新个体；
* 实验默认参数：最大代数 T=20，OBP 种群 N=20，TSP/FSSP 种群 N=10，E1/E2 父代个数 p=5，LLM 用 GPT-3.5-turbo。

### **完整流程**

**Step 0：初始化**

用 `Initialization Prompt` 调用 LLM 生成 N 个初始启发式（thought+code），在评估实例集上跑通后加入初始种群 $P\_0$，fitness 为运行得到的性能指标。

**Step 1：迭代进化（共T代）**

对每一代 $t = 1 \sim T$：

1. **子代生成**：同时启用 5 种 prompt 策略（E1/E2/M1/M2/M3），每种策略重复 N 次：
2. 按 $p\_i$ 选 1 个（M 类策略）或 5 个（E 类策略）父代 $h\_{parent}$；
3. 拼接对应策略的 prompt（任务描述 + 策略指令 + 父代 thought + code + 输出格式要求）；
4. 调用 LLM 生成新个体的 thought 和 code；
5. 可行性校验：code 可运行则在评估实例集上计算 $f\_{new}$，加入临时池；
6. **种群更新**：将临时池个体与 $P\_t$ 合并，按 fitness 升序（越小越好）排序，取 Top-N 作为 $P\_{t+1}$。

**Step 2：输出**

返回全代最优个体 $h^\* = (thought^*, code^*)$，即为 EoH 得到的最终启发式。

## **二、核心公式汇总**

**公式含义**$h\_i = (thought\_i, code\_i, f\_i)$个体三元组表示：自然语言思想、可执行代码、适应度$p\_i \propto \dfrac{1}{r\_i + N}$父代选择概率：$r\_i$ 为个体适应度排名（1 为最优），N 为种群大小，平衡优质偏向与多样性$f*{OBP} = \dfrac{1}{K} \displaystyle\sum*{k=1}^{K} \dfrac{n\_k}{lb\_k}$（K 为评估实例数）OBP 任务适应度：$lb\_k$ 为第 k 个实例的装箱下界，$n\_k$ 为启发式使用的箱子数，值越大越好（对应 excess bin 比例为 $1 - f\_{OBP}$）$f*{TSP} = \dfrac{L*{GLS} - L*{Concorde}}{L*{Concorde}}$TSP 任务适应度：gap 越低越好$f*{FSSP} = \dfrac{M*{GLS} - UB*{Taillard}}{UB*{Taillard}}$FSSP 任务适应度：gap 越低越好

### **图4：Prompt模板示例（初始化+E2）**

* 内容：左为初始化 prompt 结构：「任务描述→策略指令（设计全新启发式）→预期输出（先自然语言 thought、再 Python code，指定函数名/输入/输出格式）→注意项（禁用 random、不要额外解释）」；右为 E2 prompt，比初始化多了「5 个父代的 thought+code」模块，指令改为「先提取父代共性思想→设计基于共性但差异化的新启发式」；
* 结论：固定 prompt 结构保证 LLM 生成的 code 可直接接入 EoH 框架评估，大幅降低格式错误率；E2 的「共性提取+差异化生成」是 EoH 比纯 code 进化的 EoC 性能好的核心原因之一。

### **图6：不同方法的OBP启发式代码对比**

* 内容：并列展示 5 种方法的 OBP 评分函数（输入 item 大小、bins 剩余容量，输出评分，取最高分 bin 放 item）：
* 手工 First Fit：1 行代码，`scores=-np.arange(len(bins))`（按 bin 顺序优先）；
* 手工 Best Fit：1 行代码，`scores=item - bins`（优先剩余容量最小的 bin）；
* EoC（仅进化 code）：`log(item)*(bins²)/(item*sqrt(bins-item)) + (bins/item)^3`；
* FunSearch：`(bins-max_bin)^2/item + bins²/item² + bins²/item³` + 差分项；
* EoH（本文）：`diff + exp(diff) + sqrt(diff) + (1-diff/bins)*sqrt(diff) + 混合调整项 + 指数项混合评分`；
* 结论：手工启发式过于简单，性能上限低；EoC/FunSearch/EoH 的复杂组合结构是人类手动设计难以覆盖的；EoH 的混合多组件结构在分布外实例（如容量 500）上泛化性远好于 FunSearch（EoH gap 2.13% vs FunSearch 6.75%）。

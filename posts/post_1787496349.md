# **REEVO：作为具有反射进化的超启发式的大型语言模型**

# **一、起因**

NP 难组合优化问题（COP）长期迫使领域专家从事试错式的启发式设计；而大型语言模型（LLM）的出现，为「算法设计自动化」这一长期目标注入了新的动力。

# **二、文章内容**

* 介绍了**语言超启发式算法（LHHs）**：利用 LLMS 进行启发式生成，具有最少的人工干预和开放的启发式空间；
* 介绍了 LHHs 和带 ReEvo 的 SOTA 求解器的新应用；
* 改进了用于指导局部搜索（GLS）的惩罚启发式算法，其性能优于基于 SOTA 学习的 [52, 24, 75] 和基于知识的 ILS 求解器；
* 通过进化蚁群算法的启发式措施，改进了蚁群算法，超越了神经增强型启发式算法和专家设计的启发式算法；
* 通过进化遗传算子来改进用于电子设计自动化（EDA）的遗传算法（GA），其性能优于专家设计的 GA [63] 和 SOTA 神经求解器 [31]；
* 与经典的 HH [15] 相比，ReEvo 为旅行商问题（TSP）生成了更好的构造性启发式算法；
* 通过进化注意力重塑的启发式算法，增强了 SOTA 神经组合优化（NCO）求解器 [37, 51] 的泛化能力。

## **1、反射进化(ReEvo)**

* 集成进化搜索来有效探索启发式空间，并用 LLM 反射提供空间内的**语言梯度（language gradient）**；
* 将有效探索启发式空间的进化搜索与自我反思结合在一起，以增强 LLM 的推理能力；
* 类似于解释遗传线索，并在搜索空间内提供“语言梯度”；
* 引入了**适应度景观分析（fitness landscape analysis）**和**黑盒提示（black-box prompting）**，以实现对 LHH 的可靠评估；
* 面向 NP-Hard 组合优化问题（COPs）。

## **2、经典超启发式(HHS)**

* 从一组启发式或启发式组件中搜索最佳启发式（组合），来自动进行启发式设计；
* 纯 LHH（Pure LHH）对于黑盒 COPs 表现出有限的推理能力。

# **三、文章的贡献**

* 提出了**语言超启发式（LHHs）**的概念，将使用 LLMS 进行启发式生成的新兴尝试，与一个经过几十年发展的方法论小组联系起来；
* 提出了**反射进化（ReEvo）**，将进化计算与类人思考结合起来，以激发 LHH 的力量；引入了适应度景观分析和黑盒提示，以实现可靠的 LHH 评估，其中 ReEvo 实现了 SOTA 样本效率；
* 介绍了 LHH 的新应用，给出了带 ReEvo 的 SOTA COP 求解器，涉及**五种不同的算法类型**和**六种不同的 COP**。

# **四、文章的相关工作**

* **传统的超启发式**（classic hyper-heuristics）；
* **神经组合优化**（NCO）；
* **用于代码生成和优化的 LLMS**；
* **LLM 的自我反省**（self-reflection）；
* **组合优化的语言超启发式算法**（带 ReEvo 的语言超启发式算法）。

LHH 将 COP 规范作为输入，输出为该 COP 找到的最佳归纳启发式。Vanilla LHH 可以重复 LLM 生成来随机搜索启发式空间，但这种方式样本效率低，并且缺乏对复杂和黑盒问题的推理能力（见 §6）。因此，我们提出了反射进化（ReEvo）来解释进化搜索的遗传线索，并释放 LHH 的力量。

在进化框架下，LLM 承担两个角色：用于生成个体的**生成器 LLM（Generator）**，和用于引导产生反思的**反射器 LLM（Reflector）**。

ReEvo 作为 LHH，具有独特的个体编码：其中每个个体都是启发式的代码片段。它的进化从种群初始化开始，然后经过五个迭代步骤：**选择、短期反思、交叉、长期反思和精英突变**。我们评估了所有启发式算法在交叉和变异后的元目标（meta-objective）。提示信息收集在附录 B 中。

## **1、单独编码**

遗传编程（GP）对性能最佳的启发式算法进行优化。它与传统 GP 的不同之处在于：(1) 个体是由 LLMS 生成的代码片段；(2) 个体不受任何预定义的编码格式的限制，除了遵守指定的函数签名外。

## **2、种群初始化**

ReEvo 通过向生成器 LLM 提示任务说明来初始化启发式种群。任务规范包含 COP 描述（如果可用）、启发式指定和启发式功能。可选地，包括种子启发式算法（无论是琐碎的还是精心设计以改进的），可以提供上下文中的例子，鼓励有效的启发式方法的生成，并将搜索引向更有希望的方向。

## **3、选择**

从当前种群中选出父代对：随机选择执行成功的启发式个体，并**避免选择适应度（F 值）相同的对**，以保证后续反思有“优劣对比”可挖（详细流程见文末「算法流程」部分）。

## **4、短期反思**

Reflector LLM 拿到一对（差代码，好代码），进行对比分析，输出不超过 50 词的改进提示（hint），相当于为进化搜索提供“口语化梯度”。

## **5、跨界**

（原文标题为「跨界」，即交叉 Crossover。）Generator LLM 拿到任务说明 + 两个父代代码 + 短期反思提示，把两个父代启发式的优点缝合起来、修复已知缺陷，生成子代启发式。

## **6、长期的反思**

Reflector LLM 把历史所有短期反思记录聚合、蒸馏成一条长期提示（长期 hint），防止上下文爆炸，沉淀跨代的通用设计原则。

## **7、精英突变**

基于长期反思，对当前最优启发式（精英）做针对性微调，采样生成多个变异版本，去冲击更高的性能极限。

**带 ReEvo 的启发式生成（五种应用）**：

* 有指导局部搜索的惩罚启发式算法（GLS）；
* 蚁群优化的启发式方法（ACO）；
* 电子设计自动化中的遗传算子（EDA-GA）；
* 旅行商问题的构造性启发式算法（TSP constructive）；
* 神经组合优化中的注意力重塑（NCO attention reshaping）。

# **五、结论和限制**

* ReEvo 是为**样本效率至关重要**的场景而设计的；当允许大量的启发式评估时，反思或其他提示技术的影响可能会被掩盖；
* 基于 LLM 推理成本对 LHH 进行基准测试提出了额外的挑战：成本和处理时间是由**令牌（token）使用量**而不是查询数量驱动的，这使得基准测试过程变得复杂。

# **六、总结**

本文提出了**语言超启发式（LHHs）**和**反射进化（ReEvo）**，前者是 HHs 的一个新兴变体，后者是一种激发 LHHs 力量的进化框架。将 ReEvo 应用于五种不同的算法类型、六种不同的 COPs 以及 COPs 的白盒和黑盒视图，我们产生了最先进和有竞争力的元启发式、进化算法、启发式和神经求解器。与 SOTA LHH [47] 相比，ReEvo 显示了更高的样本效率。LHH 的发展还处于初级阶段，有望探索更广泛的应用、更好的双层优化体系结构和理论基础。我们还期待 ReEvo 通过展示遗传线索可以使用 LLMS 来解释和口头表达，从而丰富进化计算的图景。

## **与EOH的比较**

工作内容主要围绕三个方面：**(1) 搜索算法**、**(2) 下游 CO 应用**、**(3) 评估方法**。

* **搜索算法**：我们引入了反射进化算法，展示了其优越的样本效率；
* **应用**：我们的工作通过将 LHH 应用于五种不同的算法类型和六种不同的 COPs，扩大了范围，推动了 GLS、EDA、ACO 和 NCO 的最先进水平；
* **评估方法**：我们使用适应度景观分析来探索我们提出的方法的潜在机制；建立了黑盒实验环境，以确保可靠的比较和与现实世界应用的实际相关性。

# **第二轮**

# **一、关键名词学习**

## **I、去耦电容布局问题（DPP）**

它是**电子设计自动化（EDA）里的经典组合优化问题**，也是 ReEvo 论文里用来证明「LLM 进化的 GA 算子能打过专家手写 GA + SOTA 神经求解器」的核心工业场景案例。

---

### **1. 先搞懂：DPP 到底是解决什么物理问题？**

现代芯片 / PCB / 2.5D-3D IC 的**电源分配网络（PDN, Power Distribution Network）**里，IC 开关瞬间会拉很大的瞬态电流，寄生电感/电阻导致电源线出现**电压跌落（IR drop / voltage droop）和高频噪声**，严重时会造成信号错误、时序失效。

**去耦电容（decap, decoupling capacitor）**的作用本质：

* 充当**本地瞬时电荷储备**，在开关瞬间就近补充电流；
* 降低 PDN 的**输入阻抗/目标端口阻抗**（尤其在高频段），从而提升**电源完整性（PI, Power Integrity）**。

但 decap 不是越多越好、也不是随便放：

* 每个 decap 占布线面积/焊盘位、增加 BOM 成本；
* 存在**禁布区（keep-out region）**：比如探针口、关键走线区、机械开孔附近不允许放；
* decap 离“需要它的开关点/探针测量点”太远会因为寄生电感失效（效应 ∝ 距离）。

---

### **2. DPP 的形式化定义（论文采用的设定）**

**问题输入**

一个离散化的 PDN 网格（ReEvo / DevFormer 里常用 **10×10=100 个可选 port 位置**），包含三类特殊位置：

* **Probing port（探针口/目标观测端口）**：要在这里测阻抗、评估 PI 好坏；
* **Keep-out region（禁布区）**：decap 不允许放；
* **可用区域**：其余允许放 decap 的位置。

以及预算约束：

* 最多放 **K 个 decap**（$K \le K^\*$，工业里 K 通常是十几~几十量级，成本敏感）。

**决策变量**

一个解就是一个**放置方案**：

$$a = {a\_1, ..., a\_K}$$

选出 K 个合法位置放 decap（不能重复、不能在禁布区/探针口）。

**目标（黑盒性质的关键）**

$$a^\* = \arg\max\_a J(a; x)$$

* $J$：PI 目标，通常用**探针口的阻抗抑制效果 / 频段掩码达标程度**衡量；
* $x$：目标硬件上下文特征（网格坐标、层叠结构、禁区分布、频点参数等）。

**J 没有解析梯度**：每评一次通常需要调用 PDN 电磁/电路仿真器（或等效查表/快速近似求解器），因此单次评估代价很高，正好契合 ReEvo 强调的「样本效率优先」场景。

---

### **3. 为什么论文要用「GA + DPP」当 LHH 的试验场？**

专家在工业里最常用的启发式框架之一就是**遗传算法 GA**：

* 解编码：一个个体 = 长度为 K 的整数序列（表示 K 个 decap 放在哪些网格 port 上）；
* 标准流程：选择 → 交叉（crossover）→ 变异（mutation）→ 可行性修复 → 评估适应度。

但**交叉/变异算子往往靠工程师手搓**（比如：中点切半随机交换、强制修复重复位置），不一定是最优结构。

ReEvo 的做法（§5.3, Appendix C.3）：

> **不碰 GA 整体框架，只把 crossover 和 mutation 做成「由 LLM 生成的 Python 函数」**，通过进化 + 反思搜索更好的算子实现。

**论文给的专家基线GA结构（被ReEvo改进的那个）**

* 种群大小 = 20，按目标排序；
* **Elitism**：保留 Top 4 精英；
* **Selection**：从上半区选亲本；
* **Seed crossover**：把两个解各切成左右两半，随机交叉拼起来；
* **Seed mutation**：对有重复位置的个体，把非法/重复项替换成可行位置（避开 probe/keep-out）。

**ReEvo在DPP上做了什么**

* 先让 LLM 进化出更好的 `crossover(parents, n_pop)` 函数；
* 再把最好的 crossover 固定，**继续让 LLM 进化** `mutation(...)` **函数**；
* 评估方式：每个实例跑 **10 代 GA**（低 eval 预算），取 best objective。

结果：**ReEvo 生成的 GA 算子 > 专家手写 GA > DevFormer（SOTA 神经求解器）**，在线/样本效率曲线更好（Fig.3 in paper）。而且 ReEvo 这步的额外成本很低：

* 整个搜索只用约 **≤100 次启发式评估**；
* LLM 调用成本约 **$0.06/run（GPT-3.5-turbo）**，远低于一次真实 PDN 全波仿真的时间。

---

### **4. 如果你要复现/迁移DPP实验，核心要点清单**

**要点具体**网格/规模标准 benchmark 用 **10×10 PDN**，端口数 N=100约束probe 口不能放；keep-out region 不能放；一个位置最多 1 个 decap预算 K常见 K=20（也有 12/24/30 的实验变体）评估器关键：要么接官方 PDN 快速求解器/查表，要么至少对齐 DevFormer 的 reward 定义：`cost = -impedance_improvement`GA 模板先把专家版 GA 跑稳（selection/elite/feasibility repair），再把 cross/mutation 换成函数签名交给 LLM 改写黑盒 promptDPP 也可走 black-box 设定：LLM 看不到“距离/坐标物理含义”，只看到 `population, probe, prohibit, size` 等接口信息，逼它从性能比较里推断规律

---

### **5. 一句话帮你把它和前面ReEvo框架串起来**

DPP 在论文里的角色是：

**一个“单次评估很贵、工业相关、约束清晰”的黑盒 COP**，用来证明——LLM 不需要端到端训 NN，只要用反思进化去**改写搜索算子本身**（GA 的 cross/mutation 代码），就能在极低 eval 预算下超过“人写的最佳 GA”和“为该问题专门训的 Transformer（DevFormer）”。

## **II、带容量约束的车辆路径问题（CVRP）**

车辆路径问题（Vehicle Routing Problem，**VRP**）是运输、配送、物流领域的核心问题，核心目标是为车队规划从**车场（配送中心）到分散客户点**的行驶路线，以**最低成本（通常为总行驶距离）**完成配送，且路线需以车场为起点和终点。

* 它是 **TSP + 背包问题**的耦合体——既要排访问顺序（路径），又要决定“谁归哪辆车”（分簇），两个决策纠缠在一起，所以远比 TSP 难打。

VRP 可通过叠加现实约束衍生出多种细分模型：

**简化场景**

* 不考虑客户点的需求和行驶距离限制——旅行商问题（Traveling Salesman Problem，简称 TSP）；
* 车辆的容量是无穷大——多旅行商问题（Multiple Travelling Salesman Problem，简称 MTSP）。

**可行性验证**

* 判断车辆路径问题的给定实例是否存在可行解——装箱问题（Bin Packing Problem，简称 BPP）。

**现实约束**

* 每辆车都有容量限制——带容量限制的车辆路径问题（Capacitated Vehicle Routing Problem，简称 CVRP）；
* 每个客户都必须在特定的时间窗内得到服务——带时间窗的车辆路径问题（Vehicle Routing Problem with Time Windows，简称 VRPTW）；
* 供应商使用多个车场来为客户供货——多车场车辆路径问题（Multi-Depot Vehicle Routing Problem，简称 MDVRP）。

### **1、CVRP 数学模型构建**

**符号说明**

（原笔记此处为符号说明图片，现以文字列出常用符号：）

* $N = {1, 2, \dots, n}$：客户点集合；
* $0$：车场（配送中心），所有车辆从 0 出发并返回 0；
* $K$：可用车辆集合（车辆数上限）；
* $q\_i$：客户点 $i$ 的需求量；
* $Q$：每辆车的最大载重量；
* $d\_{ij}$：点 $i$ 到点 $j$ 的行驶距离（成本）；
* $D$：每辆车允许的最大行驶距离；
* $x\_{ijk} \in {0, 1}$：车辆 $k$ 是否从点 $i$ 直接驶向点 $j$。

### **模型表达式**

（原笔记此处为模型公式图片，现以文字列出：）

$$\min \sum*{k \in K} \sum*{i,j \in N \cup {0}} d*{ij} x*{ijk}$$

即最小化所有车辆的总行驶距离。

### **约束条件**

（原笔记此处为约束公式图片，现以文字列出，编号与下方「约束说明」对应：）

* (4) 容量约束：$\sum*{i \in N} q\_i \sum*{j \in N \cup {0}} x\_{ijk} \le Q, \quad \forall k \in K$；
* (5) 流量平衡：$\sum*{i} x*{ijk} = \sum*{i} x*{jik}, \quad \forall j \in N,\ k \in K$；
* (6) 距离约束：$\sum*{i,j} d*{ij} x\_{ijk} \le D, \quad \forall k \in K$；
* (7) 车场约束：$\sum*{j \in N} x*{0jk} = \sum*{j \in N} x*{j0k} = 1, \quad \forall k \in K$；
* (8) 车辆数约束：$\sum*{k \in K} \sum*{j \in N} x\_{0jk} \le |K|$。

### **约束说明**

* (4)：重量约束，每辆车的装载量不能超过其最大载重量限制；
* (5)：客户点流量平衡，进出车辆数相等，且为同一辆车；
* (6)：车辆行驶距离约束，每辆车配送不超过最大配送距离；
* (7)：配送中心约束，所有车辆从配送中心出发，完成配送任务后必须返回配送中心；
* (8)：所需车辆数量约束。

## **III、定向问题OP**

OP 的名字来自一项真实运动 **Orienteering（定向越野/徒步定向）**：选手从起点出发，地图上有许多打卡点，每个点有不同分数，你需要在**限定总时间（预算）**内回到终点，**最大化总得分**。不是所有点都来得及去，所以你必须**选择性地**挑最有价值的子集，同时安排最优路线——这就是 OP 的本质。

**目标函数：**

$$\max \sum\_{i \in V} p\_i x\_i$$

其中 $V$ 是所有节点（含起点），$p\_i$ 是节点 $i$ 的分数，$x\_i \in {0, 1}$ 表示是否访问该节点。

**约束条件：**

$$\sum*{(i,j) \in A} t*{ij} y*{ij} \le T*{max}$$

* $t*{ij}$：边 $(i,j)$ 的行驶时间，$y*{ij} \in {0,1}$ 表示是否经过该边；
* $T\_{max}$：总时间预算；
* 路线从起点出发、最终回到起点，且访问的节点形成一条连通路径（不要求访问所有点）。

## **1、**

这张图是 ReEvo 论文中的**核心框架流程图**，它非常直观地展示了算法是如何像“生物进化”一样，在 LLM（大语言模型）的帮助下不断自我迭代、变得越来越聪明的。

为了让你更好地理解，我们可以把这个复杂的图分为**“宏观进化”**（图的上半部分）和**“微观生产”**（图的下半部分）两个层面来看：

### **1. 宏观视角：进化的轨迹（图的上半部分）**

你可以把这部分看作是**“算法的历史年鉴”**。

* **彩色圆球（Rainbow Ball）**：代表**性能指标**。每一列颜色的变化（从红到黄到绿），表示随着时间推移，这一代产生的算法（灯泡图标）性能越来越好；
* **种群的演变**：系统维护着一群算法（A population of heuristics）。每一代，旧的算法会被淘汰，新的、更好的算法会被保留下来，整个种群的“智商”在不断提升。

### **2. 微观视角：一个算法的诞生（图的下半部分）**

这是整张图的**最核心区域**，展示了一个优秀的算法是如何从无到有被“制造”出来的。这个过程就像一个由 **Generator LLM（生成者）** 和 **Reflector LLM（反思者）** 组成的自动化工厂。

**第一步：Evaluate（评估） & Selection（选择）**

* **输入**：左下角的 `</>` 代表初始的算法代码（或者是上一代的精英代码）；
* **执行**：系统会运行这些代码来解决实际问题（比如你之前关心的 DPP 去耦电容布局问题），并得出**性能指标**（左上角的彩虹球）；
* **选择**：挑出表现最好的一对“父母”算法，准备生孩子。

**第二步：Short-term Reflection（短期反思）—— 吸取眼前的教训**

* **动作**：Reflector LLM（反思者）对比这对“父母”算法的好坏（Relative Performance）；
* **产出**：它不会直接改代码，而是用自然语言总结出**“为什么 A 比 B 好”**。比如：“在处理边缘效应时，A 采用了动态规划，而 B 的贪心策略导致了死锁。”；
* **作用**：这就叫**“语言梯度”**，它为下一步的“基因重组”提供了直接的指导方向。

**第三步：Crossover（交叉/杂交）—— 诞生下一代**

* **动作**：Generator LLM（生成者）登场。它拿到了父母的代码，以及刚才“短期反思”得出的改进建议；
* **产出**：它像写代码的程序员一样，把两个父代代码的优点缝合在一起，修复了已知的缺陷，生成一个全新的**子代算法（Offspring Heuristics）**。

**第四步：Long-term Reflection（长期反思）—— 沉淀跨代的智慧**

* **动作**：这是 ReEvo 区别于普通进化算法的关键。Reflector LLM 会回顾**历史上所有的“短期反思”记录**（Previous Long-term Reflection）；
* **产出**：它把这些零散的教训汇总，提炼出更高阶的**通用设计原则**。比如：“经过多代进化，我发现凡是采用‘基于图神经网络预估’的策略，在布局问题上普遍表现优异。”

**第五步：Elitist Mutation（精英变异）—— 打磨最强王者**

* **动作**：为了让当前的**最优算法（Elite Heuristic）**变得更强，Generator LLM 会参考提炼出的**“长期反思”**；
* **产出**：它不是瞎改，而是有针对性地微调最优算法的代码，生成几个变异版本（Mutated Heuristics），去冲击更高的性能极限。

### **总结：LLM 在这个图里扮演了什么角色？**

在这张图中，人类工程师被彻底解放了：

* **Reflector LLM** 充当了**“资深架构师”**：负责 Code Review，指出代码哪里写得烂，哪里写得好，并提供改进意见；
* **Generator LLM** 充当了**“天才程序员”**：负责根据架构师的反馈，把旧的代码重构、重写，甚至创造出全新的代码结构。

通过这种**“反思 →生成 →再反思 →再生成”**的闭环，ReEvo 最终能够自动进化出人类专家都写不出来的、极其高效的启发式算法。

## **2、**

这张图是 ReEvo 论文中的 **Figure 1**，它非常直观地展示了算法在一次迭代中，是如何通过 **LLM 的“反思”来指导代码进化的**。

简单来说，这就是一个 **“学霸父母生孩子，顶级教授教改良”** 的过程。为了让你看懂，我把图分为左、右两个部分来解释：

### **左侧：短期反思驱动的交叉（Crossover with Short-term Reflection）**

* **场景**：系统拿了一对表现一好一坏的父母算法，让 LLM 想办法结合它们的优点，生出更好的孩子；
* **父母辈（Parents）**：
* **坏父母（Worse）**：F=24.30（分数越高越差）。它的策略是把属性值取指数放大（`np.exp`），这导致数据差异过大；
* **好父母（Better）**：F=10.71。它的策略是用 `1 - normalized_attr`（反向优先级），表现更好；
* **短期反思（Short-term Reflection）**：Reflector LLM 对比了两个父母，得出结论（橙色文字）：“**反向打分法表现更好，说明属性值越低越好。建议在归一化后，优先处理属性值较低的边。**”；
* **孩子（Offspring）**：Generator LLM 听了反思，写出了新代码（绿色代码块）。它采用了好父母的 `inverse-priority` 思路，并具体实现了归一化公式 `(attr - min) / (max - min)`，最后取倒数 `1 / (norm_attrs + epsilon)`；
* **结果**：孩子的适应度 F=6.42，**比父母辈都要好！** 这就是“取其精华，去其糟粕”的直接体现。

### **右侧：长期反思驱动的精英变异（Mutation with Long-term Reflection）**

* **场景**：系统想对当前最强的“精英算法”进行微调，让它成为“超级精英”；
* **精英（Elite）**：当前最强的算法，F=6.36。它的代码使用了 `inverse_priority` 和 `epsilon`；
* **长期反思（Long-term Reflection）**：这是 ReEvo 的核心黑科技。Reflector LLM 不仅看这一代，还回顾了历史上的所有经验，总结出高级策略（红色文字）：“**要专注于利用实时数据动态适应启发式。强调统计分布的偏度（skewness）、峰度（kurtosis），并使用稳健统计量如中位数（median）和 MAD（绝对中位差）。**”——这相当于一位经验丰富的老教授在指点：“不要只看平均值，要看数据的分布形态是否偏移！”；
* **变异体（Mutated）**：Generator LLM 根据老教授的宏观指导，对精英代码进行了大刀阔斧的重构。新代码引入了 `median`（中位数）、`mad`（绝对中位差）、`skewness`（偏度）和 `kurtosis`（峰度）等统计学概念；
* **结果**：虽然变异后的代码 F=5.83 略高于精英（说明这次变异方向可能不是最优，或者评估存在波动），但它探索了人类专家很难想到的**高阶数学特征**。

### **总结：这张图揭示了 ReEvo 的核心逻辑**

* **LLM 不仅是生成器，更是分析师**：它不仅能写代码，还能通过 `Reflector LLM` 对比性能、分析原因，给出具体的改进建议（语言梯度）；
* **反思的层次感**：
* **短期反思**解决眼前的具体问题（为什么 A 比 B 好）；
* **长期反思**提供宏观的设计哲学（统计学分布、鲁棒性设计）；
* **自动化的算法进化**：整个过程不需要人类手写规则，LLM 在“评估 →反思 →生成”的闭环中，自主完成了算法的进化。

# **三、公式**

## **1、基于 LLM 的邻域定义**

公式 (1) 将传统超启发式的“单步变异邻域”推广为**概率性 LLM 邻域**：

$$N(h\_c) = {h \mid \text{LLM}(h \mid h\_c, x) > \xi}$$

即：LLM 在提示（prompt）$(h\_c, x)$ 下能以可测概率生成的启发式 $h$，才算是 $h\_c$ 的“邻居”。

### **符号含义**

符号补充说明：

* $h\_c$：当前启发式（中心个体）；
* $h$：候选邻居启发式；
* $x$：任务/问题描述；
* $\xi$：概率阈值，只有生成概率大于该阈值的启发式才计入邻域。

## **2、适应度景观的自相关函数 (Autocorrelation)**

公式 (2) 是适应度序列的自相关函数，用来量化搜索景观的“崎岖程度”：

$$r\_i = \frac{\sum*{t=1}^{T-i} (f\_t - \bar{f})(f*{t+i} - \bar{f})}{\sum\_{t=1}^{T} (f\_t - \bar{f})^2}$$

由此可引出 **correlation length**：$l = -1 / \ln(|r\_1|)$，$l$ 越小表示景观越崎岖。

## **公式1和2的作用**

### **总结：这两个公式在 ReEvo 里的作用**

公式 (1) 和 (2) 配合起来，构成了一个**“难度探测器”**：

* 先用**公式 (1)** 搞清楚 LLM 能给代码空间提供多大的探索自由度；
* 再用**公式 (2)** 去评估这个空间的“崎岖程度”。

## **🔄 一、ReEvo 算法流程（对照 Fig.1）**

ReEvo = **进化搜索（Genetic Programming 变体）** + **LLM 双角色（Generator + Reflector）** + **双层反思**。个体编码是“一段 Python 启发式代码”，不预设语法空间。

**整体循环（每代 5 步）：**

```
输入：COP 任务描述 + 可选 seed heuristic
输出：最优启发式 h*
```

1. **Population Initialization**：给 Generator LLM 喂 task spec（+seed），温度 +0.3，生成 30 个初始 heuristic（种群 size=10，但初始多生成些）；
2. **Selection**：从执行成功的 heuristic 中随机选父代对，**避免选 F 值相同的对**（保证反思有“优劣对比”可挖）；
3. **Short-term Reflection**：Reflector LLM 拿到一对（差代码, 好代码），做**对比分析**，输出 <50 词的改进 hint → 类比“口语化梯度”；
4. **Crossover**：Generator 拿到 task spec + 两父代码 + 短期反思 hint，生成子代 heuristic\_v2；
5. **Long-term Reflection**：Reflector 把历史短期反思聚合，蒸馏成一条长期 hint（防止上下文爆炸）；
6. **Elitist Mutation**：基于长期反思，对当前最优 heuristic 做精英变异，采样多个改进版。

> 📌 评估（meta-objective F）在 **crossover 后和 mutation 后各做一次**，用 mini 训练集上的平均性能估计。Table 8 超参：pop=10, max\_eval=100, crossover\_rate=1, mutation\_rate=0.5, LLM=gpt-3.5-turbo, temp=1。

**五个应用分支的 heuristic 接口不一样**（Appendix B 的 Prompt 10 列全了）：

* ACO 系 → `heuristics()` 返回 η 矩阵（塞进 ACO 转移概率）；
* GLS → `heuristics()` 返回 penalty 权重；
* DPP\_GA → `crossover()` / `mutation()` 换算子；
* TSP\_constructive → `select_next_node()` 确定性构造；
* NCO → 返回 $h\_{(c)j}$ 加到 attention logits 上（公式 4/6）。

## **🧮 三、公式清单（按出现顺序）**

**公式 (1) — LHH 邻域定义（§6.1）**

$$N(h\_c) = {h \mid \text{LLM}(h \mid h\_c, x) > \xi}$$

> LLM 在 prompt $(h\_c, x)$ 下能以可测概率生成的 $h$，才算是 $h\_c$ 的“邻居”。把传统 HH 的“单步变异邻域”换成了**概率性 LLM 邻域**。

**公式 (2) — 自相关函数（§6.1）**

$$r\_i = \frac{\sum*{t=1}^{T-i} (f\_t - \bar{f})(f*{t+i} - \bar{f})}{\sum\_{t=1}^{T} (f\_t - \bar{f})^2}$$

> 随机游走 $i$ 步后的适应度相关性，用来量化**景观崎岖度**。引申出 correlation length $l = -1/\ln(|r\_1|)$，$l$ 越小越崎岖。

**公式 (3) — 原 NCO（重编码器轻解码器）logit（Appendix C.4 引 POMO/Kool）**

$$u*{(c)j} = \begin{cases} C \cdot \tanh\left(\dfrac{q*{(c)}^T k\_j}{\sqrt{d}}\right), & j \in \pi\_{<t} \ -\infty, & \text{otherwise} \end{cases}$$

> 标准 Transformer 缩放点积 + tanh 限幅 + visited 掩 $-\infty$。

**公式 (4) — ReEvo 的 attention reshaping（§5.5 核心）**

$$u*{(c)j} = \begin{cases} C \cdot \tanh\left(\dfrac{q*{(c)}^T k\_j}{\sqrt{d}} + h*{(c)j}\right), & j \in \pi*{<t} \ -\infty, & \text{otherwise} \end{cases}$$

> 唯一改动：softmax 前 **+ $h\_{(c)j}$**，$h$ 是 ReEvo 生成的 heuristic 矩阵（TSP/CVRP 里 $h\_{(c)j} = H[c,j]$）。零额外推理开销。

**公式 (5)(6) — 轻编码器重解码器（LEHD 类）的 reshape**

$$u\_i = W\_o h\_i, \quad u\_i = W\_o h\_i + H\_{c,i}$$

> 更直接：在输出线性层后再叠一项 $H$，不碰 attention 内部。

## **🔮 四、未来工作（§7 + §8 + Appendix A）**

论文明示的几个方向：

1. **LLM 能力依赖**：当前反射在 GPT-3.5+/GPT-4 才稳，开源 70B 级有时统计显著不够 → 等 LLM 继续涨，范式只会更好；

3. **更广的 LHH 应用**：论文说 ReEvo 其实能迁到**任意字符串优化场景**（prompt tuning 初步试过优于 random/GP）→ 非 COP 领域（RL reward design、NAS prompt、一般代码优化）是空白；
4. **o1 类推理 LLM**：Appendix A.2 点了一句——o1 这种带内在推理的模型可能进一步把样本效率和上限推上去，是“有趣的后继实验方向”；
5. **理论地基**：LHH 的搜索复杂度、收敛性、景观理论（本文只做了自相关实证）基本是空白；
6. **与 NCO 的互补定位**：论文讨论了 Rule-based（LHH）vs NN-parameterized（NCO）的取舍——分布漂移/对抗/动态环境里 LHH 可解释性占优，复杂环境里 NCO 表达力占优，两边融合（如本文 §5.5 把 LHH 当 NCO 插件）会继续出活。
